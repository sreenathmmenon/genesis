# Genesis — Agentic Use Cases (Researched, Verified, Honest)

---

## What makes something genuinely agentic

Seven problem archetypes that require an agent — not just automation:

| # | Archetype | Why automation fails | Why agents work |
|---|---|---|---|
| 1 | **Monitor feeds for the signal that matters** | Every alert looks equal in a list | Agent reads content, judges importance, stays silent on noise |
| 2 | **Read a large document corpus and extract what's relevant** | Keyword search finds occurrences, not meaning | Agent reads context, understands intent, identifies what matters |
| 3 | **Synthesise messy multi-source inputs into one narrative** | Dashboards show numbers; nobody writes the "why" | Agent reads multiple sources, finds the connecting thread |
| 4 | **Research briefing before a meeting or action** | Search returns links, not conclusions | Agent reads the content, forms a view, delivers a brief |
| 5 | **Draft the document that requires evidence synthesis** | Templates fill fields; they don't reason | Agent reads evidence, forms arguments, writes in context |
| 6 | **Track changes over time and flag meaningful deviations** | Alerts on any change; impossible to tune | Agent assesses whether the change is significant and why |
| 7 | **Connect signals across sources to detect a risk or opportunity** | Each tool sees its own domain only | Agent reads across domains, finds the pattern no single tool sees |

---

## What Genesis can actually do (verified from code)

**Tools:** `web_search` (DuckDuckGo — titles, URLs, page excerpts), `http_request` (any REST API), `github_api` (PRs, issues, commits, diffs, files), `file_reader` (local files up to 50KB), `telegram_send` (Telegram messages), `scheduler` (set/change cron)

**Execution:** Multi-node LangGraph graphs. Each node: up to 10 rounds of LLM → tool call → result → reasoning. Nodes share context — each node sees all prior outputs. Self-healing on failure.

**What is NOT possible today:** writing/committing code, Slack/email, database queries, JavaScript-rendered pages, file uploads. Honest.

## Summary: What all 75 have in common

Every use case above follows the same structural pattern:

```
Unstructured or multi-source input
        ↓
Agent reads and understands content (not keyword match)
        ↓
Agent makes a judgment call (is this significant? what does it mean?)
        ↓
Agent adapts based on what it found (path changes mid-run)
        ↓
Agent delivers a conclusion or action (not a data dump)
        ↓
Agent stays quiet when nothing is worth surfacing
```

The last step — **staying quiet when nothing is worth surfacing** — is what separates a useful agent from a noisy automation. An alert that fires on everything trains users to ignore it.
